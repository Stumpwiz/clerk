MAILING LISTS ARCHITECTURE (COMPLETED)

A dedicated mailing-list subsystem now exists, separate from roster/PDF reports.

Backend API
- `GET /api/mailing-lists`
- `GET /api/mailing-lists/{id}`

Purpose
- Metadata-driven plaintext mailing list generation.
- Same UX pattern as reports, but logically separated.

Current mailing lists
- Residents Council Officers (`rc-officers`)
- Committee Secretaries (`committee-secretaries`)
- Committee Chairs (`committee-chairs`)
- Hall Reps (`hall-reps`)

Business rules
- Committee Secretaries:
  - selects people with a current linked `Term` whose associated `Office.title` is exactly `"Secretary"`.
  - intentionally includes the Residents Council Secretary.
- Committee Chairs:
  - selects people with a current linked `Term` whose associated `Office.title` is exactly `"Chair"`.
- Hall Reps:
  - existing logic retained.
- Residents Council Officers:
  - existing logic retained.

Formatting rules
- one email per line
- comma after each line except the final line
- suitable for direct Outlook paste
- blank/null emails excluded

Implementation details
- Shared helper logic: `backend/app/utils/mailing_lists.py`
- Dedicated router: `backend/app/routers/mailing_lists.py`
- Reports API now returns only report/PDF entries.
- `/api/reports/pdfs` endpoints are restricted to PDF artifacts only.

Legacy compatibility
- Legacy endpoints retained under `/api/reports`:
  - `/api/reports/rc-officers`
  - `/api/reports/committee-secretaries`
  - `/api/reports/hall-reps`
  - `/api/reports/rc-officers-and-chairs`
- `/api/reports/rc-officers-and-chairs` now intentionally behaves as Committee Chairs.

REPORTS SYSTEM (CURRENT)

Registry-driven reports remain in:
- `backend/app/routers/reports.py`

Report metadata API
- `GET /api/reports`

Report generation pattern
- `/api/reports/{id}`

PDF artifact routes
- `/api/reports/pdfs/{filename}`

Rosters & Reports now contains only true report/PDF artifacts:
- `short-roster`
- `long-roster`
- `vacancies`
- `expirations`
- `terms-report`

Terms report rules (preserved)
- excludes `end = 9999-12-31`
- excludes title `Liaison` and `Staff`
- sorted by `body_precedence`, `office_precedence`, `first`, `last`

PDF pipeline (preserved)
- Jinja2 -> XeLaTeX -> PDF
- main utility: `backend/app/utils/pdf_generator.py`
- templates: `backend/files_roster_reports`

IONOS short-roster publish (preserved)
- triggered by `GET /api/reports/short-roster`
- uploads to `/mrra/documents/roster.pdf` via SFTP
- credentials from AWS Secrets Manager
